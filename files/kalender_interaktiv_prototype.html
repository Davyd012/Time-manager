01

Hva som faktisk skal endres

Prioriter overgangen og interaksjonene. Behold appens eksisterende grafiske identitet og fungerende timeføringslogikk.

P0 / GESTER

Dra fra hele flaten

Åpne fra egnet hovedområde og håndtak; lukk fra kalenderens kort, header og tomrom. Knapper og datovalg må fungere uforstyrret.

P0 / BEVEGELSE

Én styrt overgang

Én kontinuerlig progress-verdi styrer posisjon, clipping og visning. Ingen nye tween-animasjoner for hver pointer-bevegelse.

P0 / TILSTAND

Ingen re-entry

Hjem beholdes i komposisjonen. Tomtilstanden skal ikke kjøres gjennom en enter-animasjon ved kalenderlukking.

P1 / LAG

Ingen ghosting

Bruk en tydelig opaque kalenderflate. Unngå ukestripe, kalenderdager og overskrifter oppå hverandre.

P1 / INNHOLD

Nyttig kalenderrom

Vis månedssum, markert dag og dagsregistreringer under kalenderen. Gjør all nødvendig tekst lett å lese.

P1 / POLERING

Diskret finish

Sandfarget aksent, gjennomgående norsk, god berøringsstørrelse, rolig fjær og stabil bunnnavigasjon.

02

Interaksjonsregler

Alle bevegelser skal være direkte, forutsigbare og avbrytbare – uansett hvilken tilstand kalenderen er i.

HandlingOppførsel
Dra opp på HjemKalenderflaten følger fingeren fremover, også fra hovedområdet.
Dra ned i KalenderSamme overflate føres tilbake. Ingen separat navigation-pop-animasjon.
Slipp tidligRolig retur til samme anker; ikke et rykk eller hopp.
Raskt sveipHastighet kan avgjøre anker selv om fingeren ikke dro hele distansen.
Ny gest midt i animasjonenAvbryt settle og overfør kontroll umiddelbart til fingeren.
Trykk på dato eller knappVanlig handling. Ikke utilsiktet drag eller lukking.
Scroll i detaljlisteInnhold scrolles først; nedtrekk lukker først når scroll er øverst.
System-tilbake / redusert bevegelseKalender lukkes først; alternativ eksplisitt kontroll og kort/ingen animasjon.
03

KMP-arkitektur

Det er arkitekturen, ikke bare en annen animasjonskurve, som avgjør om opplevelsen faktisk blir bra.

HomeCalendarHost
├── TransitionState (0.0 → 1.0)
├── HomeContent       [beholdt]
├── CalendarSurface   [samme offset]
├── SharedHeader      [samordnet]
└── BottomNavigation  [stabil]

Anchors:
  Collapsed → 0 px
  Expanded  → beregnet høyde

Gest:      direkte offset
Release:   ett settle
Rendering: én samlet progress
  • Tilstand: Behold Home-ViewModel og valgt dato på samme sted.
  • Gest: `AnchoredDraggableState` når tilgjengelig i prosjektets Compose-versjon.
  • Scroll: Koordiner med `nestedScroll`, ikke to konkurrerende `pointerInput`.
  • Rendering: Bruk `Modifier.offset { ... }` eller `graphicsLayer { ... }` der det er riktig.
  • Navigasjon: Ikke push en ny rute samtidig som panelet åpnes.
  • Ytelse: Unngå full-tree recomposition for hver drag-frame.
Viktig: En video kan vise symptomer, men ikke bekrefte om årsaken er `AnimatedVisibility`, navigasjon, `LaunchedEffect` eller state-reset. Kodeassistenten må finne den faktiske årsaken i kildekoden.
04

Klar for implementering

Bruk prompten nedenfor sammen med begge videoene i kodeassistenten. Hele spesifikasjonen er også tilgjengelig som egen Markdown-fil.

Les detaljert .md-plan
Implement a premium, gesture-driven, unified Home ↔ Calendar experience in our Kotlin Multiplatform / Compose Multiplatform time-tracking app. Use the two supplied recordings as reference. Preserve our dark style, sand-colored accents, existing components, bottom navigation and functional behavior.

FIRST INVESTIGATE: inspect Home/Calendar composables, ViewModels, route transitions, nested scrolling, drag handling, AnimatedVisibility/AnimatedContent, LaunchedEffect, keys and loading state. Report observed root causes with file/line references; do not infer code behavior from video alone.

STRUCTURE: create a single HomeCalendarHost with a persistent Home state, one transition controller, collapsed/expanded anchors and one progress/offset source of truth. Prefer AnchoredDraggableState and anchoredDraggable in commonMain if compatible with our Compose version. Calculate anchors from measured area/insets, not screen pixel constants. Do not trigger a second navigation animation when the panel finishes opening.

GESTURES: support upward drag from main Home content/handle and downward drag from Calendar header/grid/non-control areas. Respect directional touch slop, native click behavior on date cells/actions, horizontal gestures, velocity fling, cancelled gestures and interruption. Use nested scroll when the Calendar details have a scrollable list.

ANIMATION: during drag move the panel directly with the finger; no tween per gesture delta. On release use exactly one subtle, interruptible settle spring. Use a coherent opaque/clipped calendar surface rather than crossfading text from both screens. Coordinate header and panel changes via the same progress; no duplicated labels, overlapping weekday strips, ghosting, sudden snapping or extra route animation. Keep the bottom bar fixed.

STATE: returning from Calendar must reveal the already-existing Home illustration, labels and CTA without replaying their initial entrance or refetching data unnecessarily. Diagnose remounts, effect restarts, unstable keys, loading flicker and separate animation controllers. Preserve selected date and time entries.

POLISH: consistent Norwegian localization, readable month summary, clearly selected/today dates, approximately 44–48dp tappable dates, useful selected-day section below the grid, system-inset safety, accessible button to open/close and reduced-motion support. Keep the existing aesthetic; do not redesign unrelated screens.

PERFORMANCE: defer frequently changing offset and alpha state to layout/draw lambdas where possible; avoid recomposing the whole Home tree per frame; precompute calendar dates and keep stable keys. Verify Android and iOS behavior where supported.

DELIVERABLES: explain root causes; implement changes; list edited files; test slow dragging, flings, release below threshold, drag-interruption, taps on controls, nested scrolling, back handling, no visual overlap, fixed bottom nav, 20+ rapid open/close cycles, no Home re-entry, and no selected-date reset. Be explicit about which tests were actually run and which could not be verified on hardware.
Dette er et selvstendig UX-konsept for implementering. Ingen appkildekode er modifisert. Tall, måned og registreringer i prototypen er demonstrasjonsinnhold.
