## Implementation detail and handoff

The following describes the current shared implementation. Each function is in the same-named Kotlin file under `shared/src/commonMain/kotlin/no/timnor/app/shared/features/`, unless another path is given.

### `TimnorHomeScreen` (`root/presentation/home/`)

- Inputs: `TimnorHomeUiState`, ViewModel, Home-reselection counter and callbacks for Month View, Settings, export, share and expansion reporting. Project/work data and selected date are read from state; the composable owns sheet visibility and calendar animation state.
- Expansion: saveable expanded target starts collapsed; an `Animatable` tracks 0–1. A drag updates transient progress; settling starts from the drag position and springs to an endpoint, or snaps when system animations are disabled. `calendarExpanded` becomes true at progress ≥ 0.5; this is what the host is told. Home reselection animates closed. Drag distance is available height less measured collapsed header/calendar heights, clamped to at least one pixel.
- Header add and empty-list add call `beginManualWork()` before opening the editor. An existing `editingWorkId` also opens it. Save and period-save close only after their callback reports success. Cancel/dismiss closes and calls `cancelWorkEdit()`. Deletion looks up the currently edited work and reports success if it has already disappeared. Preserve callback order when changing the UI.
- Displays state errors above the calendar. Export dialog is only accessible if an export callback exists; confirming dismisses the dialog and forwards year, 1-based month and optional IDs.
- Verify: resize/recreate during a drag, reselect while animating, missing project list, failed saves and export cancellation. The source does not establish the reference spring or visual alignment; measure both before adjusting.

### `HomeHeaderBar` and `HomeCalendarToggle`

- Header shows the localized selected weekday, Settings, optional export and add. Add is disabled without projects. Tapping weekday toggles calendar; dragging vertically uses `calendarExpansionTarget`: velocity above threshold wins, otherwise progress ≥ 0.5 opens. The header shrinks/fades with progress and clears semantics near fully expanded.
- Toggle is a separate centered control under the week strip. Compare its actual visual and semantic state with legacy `HeaderWidget`; test keyboard/assistive activation as well as tap. Keep Settings/export/add taps independent from dragging.

### `CalendarSection`, `CalendarExpandedToolbar`, `CalendarProgressContent`, `CalendarMonthTransitionContent`

- `CalendarSection` computes a Monday-based week from the selected date and aggregates work by the stored UTC date. It owns filter-sheet visibility and a month-transition lock. The vertical draggable clamps progress to 0–1 and uses the same velocity/halfway rule as the header. It also exposes an accessibility action to toggle expansion.
- While expanded, the section can scroll; the toolbar also participates in vertical drag. Month changes are accepted only when expanded content is enabled, target differs, and a transition is not already active. Lock clears after 320 ms with animations, immediately without. Test if rapid swipe and arrow requests are intentionally dropped; do not remove the guard without addressing concurrent transitions.
- `CalendarProgressContent` fades the week out and overlays month content during expansion; it removes week semantics after expansion begins. `CalendarMonthTransitionContent` animates month content. Inspect its outgoing/incoming layers when testing: only the intended current layer should accept input and semantics.
- Verify gesture arbitration: drag down from collapsed header and week; drag up from expanded toolbar/body; short drags on either side of halfway; fast flings in each direction; cancellation; vertical scrolling; horizontal month swipes; touches on day and action buttons. Check both reduced motion and normal motion.

### `CalendarWeekStrip`, `CalendarDayCell`

- The week is seven dates beginning Monday, including dates from neighboring months. Legacy keeps its Home header/week controls visible and date taps enabled until expansion reaches 0.5, then replaces that header with the expanded calendar header. Shared now preserves week-row opacity, semantics and date/toggle interaction until that same midpoint; adjacent-month dates remain disabled. Tapping an enabled date invokes selection.
- `CalendarDayCell` displays weekday abbreviation and day number. In-month dates also display the rounded hour total, including `0` in the regular layout; compact layout hides a zero total as legacy does. Adjacent-month cells keep their weekday/day number but omit hours and are disabled. Selected, enabled and disabled states use theme colors; selection animates color and scale unless reduced motion. It uses a compact layout for width under 48dp or font scale above 1.15. Selected semantics are exposed.
- Verify the apparent inability to select an adjacent-month date against legacy. Do not automatically enable it: check whether the ViewModel also changes the displayed month and whether this is intended. Test a week straddling December/January, empty totals and large font.

### `CalendarMonthContent`, `CalendarMonthGrid`, `CalendarMonthDayCell`

- `CalendarMonthContent` filters visible entries using selected project IDs, groups by day and computes total. Month arrows and a horizontal drag of at least twice the extra-large spacing navigate one month; drag is consumed and canceled drags reset the accumulated distance. Navigation is available only while interactive. Transitions slide/fade by direction when animation is enabled.
- Current title click opens Month View on day 1. Grid taps update a saveable, Home-screen-local selected date used only for the grid highlight. Legacy `MainPageContent` similarly stores `selectedCalendarDateText` locally and passes it to `HeaderWidget`/`MonthGrid`; week selection and the daily work list remain tied to the ViewModel's selected date. The Month View title action does not change that local highlight.
- Grid lays out leading/trailing blanks to complete weeks. Day cells show day and formatted total (or `0`), expose selected semantics, and are disabled during transitions. `SharedCalendarGestureTest.selectingMonthGridDayOnlyChangesGridHighlightLikeLegacy` asserts the grid selection leaves the Home ViewModel date unchanged and does not open Month View; Android runtime execution still requires a device. Compare sizes, separators and typography with matching captures.
- `visibleWorks` treats `selectedProjectIds == null` as all works. A non-null selection includes only IDs that are both selected and currently valid. Test all, subset, empty set and deleted project. Do not conflate `null` with empty set.

### `HomeDailyWorkList`, `RecentWorkRow`

- List filters by selected UTC date through `monthViewWorksForDate` and currently delegates populated rendering to `MonthViewTimeline`, empty rendering to `MonthViewEmptyState`. It fades to transparent by progress 0.25, hides semantics and consumes pointer events only above progress 0.8, then is removed at progress 1. Test that this does not trap a drag or leave an invisible tappable row.
- `RecentWorkRow` exists as a shared component, but this list does not call it. Before modifying it to change the active screen, trace its call sites. Compare the active timeline with legacy `ListOfWorksDaily`, including entry order, duration and click-to-edit.

### `ProjectFilterSheet`, `ProjectFilterRow`

- Selection begins as the passed set (`null` means all); query is saveable. Search trims input and matches project names ignoring case. Select-all toggles only visible search results using the full set of project IDs. Monthly project totals are calculated from all supplied work for the displayed month, independently of the current selection.
- Back icon and Done both apply selection and dismiss; outside/back sheet dismissal invokes `onDismiss` without applying. This distinction is observable and must be tested against legacy before changing it. The sheet can temporarily show all rows unchecked, but Apply normalizes an empty selection to all projects, matching legacy's empty-list repository behavior. Rows use stable IDs and each toggle goes through `toggleProjectSelection`.
- `ProjectFilterRow` must preserve a single accessible checkbox action for row and checkbox, with project name, hours and checked state. Test search → select visible → clear search, none/all, no matches, cancel and apply. Check project changes while the sheet is open.

### `TimnorMonthExportDialog`

- Initializes to the device-local current month/year, not necessarily the calendar month. Project chips start unselected; confirming an empty selection forwards `null` (all projects), otherwise the explicit set. It displays twelve month chips and previous/next year controls; cancel/dismiss emits no export. This contract is separate from filter-sheet empty-set semantics. The dialog now uses the legacy custom surface layout, export title icon, project-chip row with selected checkmarks, three-column month buttons, directional year icons and side-by-side cancel/export actions, with theme shapes and spacing for the shared Material 3 implementation.
- Legacy Home's export dialog also starts at the current month/year and uses an empty project selection to mean all. Its displayed year is dropped by the legacy callback (`CreateExcelDocument` accepts only a month), and the legacy ViewModel therefore exports that month in the current year. Shared preserves the user's chosen year and routes year, 1-based month and optional project IDs through `TimnorSettingsViewModel.exportSpreadsheet`; this fixes the inert legacy year control while retaining the file format and all-project default. The new `spreadsheetDialogForwardsSelectedYearMonthAndProjectSubset` Android UI test covers the selected year/month/project path.
