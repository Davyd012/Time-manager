# Timnor iOS host

Open `Timnor.xcodeproj` on macOS with Xcode 26.4. The Xcode build phase invokes
the repository Gradle wrapper to build and embed the static `TimnorShared`
framework for the selected iOS device or simulator. The SwiftUI app hosts the
shared Compose project list, creates projects, and adds manual work entries through the iOS file-backed
`TimnorPersistence` implementation.

The host uses bundle identifier `no.timnor.ios`. It is a separate iOS identity;
the Android application ID remains `no.timnor.app`.

The current host slice supports project listing/create/edit/delete, manual
work create/edit/delete, a monthly work summary, and an iOS stopwatch that stores elapsed/start state and
derives elapsed time while active. SwiftUI file save/open flows use the shared
version-1 JSON backup codec and show record counts before replacing data. The
host can also save a monthly `.xlsx` report generated by shared Kotlin code.
Notifications are not implemented in this iOS shell. None of these iOS paths
have been compiled or exercised on a simulator; the stopwatch does not promise
continuous background execution. See
`docs/ai/timnor-migration/HANDOFF.md` for the current acceptance gaps.

The Windows build cannot execute Xcode or Kotlin/Native iOS targets. Build and
run the Xcode project on macOS before treating this host as validated.
See `docs/ai/timnor-migration/PLATFORM-BUILDS.md` for the available Android and
iOS build/acceptance steps and current compatibility limits.
